# Дневник боли

Настольное приложение для ведения локального дневника приступов боли. Оно позволяет записывать продолжительность, интенсивность, симптомы, возможную причину и время приступа, а затем просматривать историю и графики.

> **Статус проекта:** учебный проект, завершённый в 2023 году. Приложение хранит данные локально и не передаёт их на внешний сервер.

> **Важно:** приложение создано в учебных целях и не является медицинским изделием. Оно не ставит диагнозы и не заменяет консультацию врача.

## Возможности

- создание записей о приступах боли;
- редактирование и удаление записей;
- сохранение продолжительности, интенсивности, симптомов и возможной причины;
- фиксация даты и времени;
- сортировка истории по дате, продолжительности или интенсивности;
- график частоты приступов;
- график средней продолжительности;
- локальное хранение данных в SQLite.

## Технологии

- Python;
- PyQt5 и Qt Designer;
- SQLite;
- Matplotlib;
- NumPy.

## Структура проекта

```text
app.py                     Логика приложения и работа с базой данных
main_window.ui              Главное окно с таблицей и графиками
dialog_new_seizure.ui       Форма создания и редактирования записи
dialog_delete_seizure.ui    Подтверждение удаления
base.db                     Демонстрационная база SQLite
requirements.txt            Зависимости Python
```

## Локальный запуск

Проект использует версии библиотек 2022–2023 годов. Для наиболее предсказуемого запуска рекомендуется Python 3.10.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Mr-Zoom-13/pain-diary.git
cd pain-diary
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Активация в macOS или Linux:

```bash
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Запуск приложения

```bash
python app.py
```

Приложение открывает демонстрационную базу `base.db`, расположенную в корне проекта. Все созданные записи сохраняются в этот файл.

## Хранение данных

В репозитории находится демонстрационная база с тестовыми записями. При использовании приложения для собственных данных рекомендуется создать отдельную локальную копию проекта и не публиковать изменённый файл `base.db`.

Данные не шифруются. Любой пользователь с доступом к файлу базы может открыть его с помощью инструментов для SQLite.

## Ограничения

- приложение рассчитано на одного локального пользователя;
- интенсивность, симптомы и причины вводятся как свободный текст;
- экспорт, резервное копирование и синхронизация не реализованы;
- введённые медицинские данные не защищены паролем или шифрованием;
- совместимость с современными версиями Python и библиотек не проверялась.
